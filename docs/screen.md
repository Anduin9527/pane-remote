# 看屏幕模块

中文 | [English](en/screen.md)

在手机上看和操作电脑的屏幕：整块显示器，或者只看某一个窗口。登录和兜底用 macOS 自带的「屏幕共享」，画面由电脑上的小助手 mousectl 用系统的 ScreenCaptureKit 录，不用装第三方远程桌面软件。只支持 macOS，默认关闭。

```bash
pane-remote enable screen                 # 装鼠标助手 mousectl，并列出要你手动做的几步
pane-remote enable screen --create-cert   # 同上，另外建一张本机自签名证书给 mousectl 签名（见下文「签名证书」）
```

开启后手机顶栏会多一个屏幕图标，点开用电脑的用户名和密码登录。

## 能做什么

顶栏只有一行：左边关闭和「画面来源」下拉框（显示器 / 当前窗口 / 选择窗口…），右边是键盘、操作方式（直接点 / 触控板）和「更多」（画质、点到输入框自动弹键盘、横过来、整块屏、调整窗口大小、切回原来的前台 app）。

- **看一块显示器**：在画面来源里选（★ 是主屏）；画质「省流」按「点」的分辨率发（像素少 4 倍），「清晰」按实际像素发
- **只看一个窗口**：「选择窗口…」列出所有能录的窗口（含别的桌面上的、台前调度收起来的，台前调度把后台打开的窗口缩成很小的缩略图也照样列出），可以搜索。只录这一个窗口，不切到前台；第一次点它时才切到前台，「更多 → 切回原来的前台 app」把原来的前台 app 切回来
- **关窗口、退出 app**：窗口列表里每个窗口右边有 ×，按的是这个窗口自己的关闭按钮（跟在电脑上点红叉一样，app 要问保存会弹它自己的框）。每个 app 有「退出」（正常退出，app 能保存），要在 3 秒内点两次才生效；正常退出 3 秒后还在运行才出现「强制退出」，同样要点两次。访达、程序坞、Spotlight 这些系统进程不给退出
- **调整窗口大小**（看窗口时，「更多 → 调整窗口大小」）：拖右边、下边或右下角的手柄，手机上先画出目标轮廓，松手才改一次；也有「适合手机」（按手机屏幕比例尽量大、居中）、「占满」、「左半」、「右半」（都按窗口所在显示器去掉菜单栏和程序坞后的区域）
- **后台打开 app**：窗口列表下面是没开窗口的 app，「后台打开」不抢前台，窗口开出来后自动切过去看。只有菜单栏图标的 app 显示「唤出」：Spotlight 按系统设置里它的快捷键，uTools 按它自己设置里的唤出快捷键，别的点一下它的菜单栏图标
- **直接点模式**：轻点 = 点击，长按 = 右键，长按后拖 = 按住左键拖，单指滑 = 滚动，双指 = 缩放 / 平移（只在手机上放大，不影响电脑）
- **触控板模式**：手指滑动挪光标，轻点 = 在光标处点击，双指滑 = 滚动，双指捏 = 缩放（画面跟着光标走）
- **打字**：键盘按钮打开输入框，打的字整段发过去（含中文和输入法上屏的文字）。快捷键栏跟终端页一样：第一行是最常用的（⌘、Esc、Tab、回车、删除、左右方向键、⌘C、⌘V），其余（⌥ ⌃ ⇧、上下、⌦、Home / End / PgUp / PgDn、⌘X / A / Z / ⇧Z / S / F / W / T、⌘Tab、⌘空格）收在「⋯」里；修饰键对下一个键生效，比如先点 ⌘ 再打 c 就是复制。快捷键栏和输入框跟着手机键盘走，不会被键盘挡住
- **点到输入框自动弹键盘**（「更多」里打开，默认关）：点到电脑上的输入框，手机键盘自己弹出来，并把输入光标挪到键盘上面看得见的地方（见下文「自动弹键盘怎么判断」）
- **锁屏时也能打字**：电脑锁着屏时，输入的字和按键改走屏幕共享（见下文「锁屏」），在画面里输密码就能解锁
- **多指手势**（跟 Mac 触控板一样，换成系统快捷键发过去）：三 / 四指上滑 = 调度中心，下滑 = 应用程序窗口（App Exposé），左右滑 = 切桌面，张开 / 捏合 = 显示桌面，三指轻点 = 查询（Look Up）
- **横过来**：竖着拿手机也能把整个界面转 90°，看宽屏方便

## 结构

```
手机 noVNC（web/src/lib/screen/ScreenView.svelte）
   │ WebSocket /api/screen/vnc?view=屏序号,清晰
   ▼
pane-remote 服务（server/screen.mjs，只转字节）
   │ bridge 的 screen 指令（local 模式直接执行，relay 模式经 SSH 反向隧道）
   ▼
转码代理（agent/screen/proxy.mjs，电脑上）── 画面（整块屏 / 窗口）、鼠标、键盘、文字、焦点、窗口大小 ── mousectl（LaunchAgent，unix socket）
   │ RFB，127.0.0.1:5900：登录认证；mousectl 录不了时的画面；锁屏时的键盘
   ▼
macOS 屏幕共享
```

窗口列表、app 列表、后台打开、关窗口、退出 app 走普通的 HTTP 接口（`GET /api/screen/displays|windows|apps`、`POST /api/screen/launch|summon|close|quit`），最后也是 bridge 去问 mousectl。

## 画面从哪来

整块显示器和单个窗口走同一条路：mousectl 用 ScreenCaptureKit 录（整块屏是 `w stream s<屏序号>`，带鼠标指针；窗口是 `w stream <窗口号>`），转码代理自己比较前后两帧找出真正变了的区域再发。屏幕共享的连接仍然保留：登录认证靠它，mousectl 不在、太旧或录不了时退回它出画面。

为什么不直接用屏幕共享的画面：测试中苹果的屏幕共享会出两种毛病：

- **不再推增量**：有时第一帧之后就不再推送变化，画面看着像卡住（新旧两版转码代理都一样，问题在屏幕共享这边）
- **冷启动黑屏**：屏幕共享进程冷启动后的第一个登录连接整场都是黑画面（见下文）

整块屏的录制意外断了（比如 mousectl 重启）会隔 1 秒重试，最多 3 次，都不行这一场就改用屏幕共享。连上 4 秒还没收到画面（旧版 mousectl 不认整块屏的指令，或者没给「屏幕录制」授权）也直接改用屏幕共享。

## 为什么要转码代理

直接把屏幕共享的数据转给手机不行：

- **太大**：苹果的屏幕共享只给 ZRLE 编码，对照片、壁纸几乎压不动，一块 4K 屏第一帧就十几 MB；relay 模式下中转服务器带宽小时要等半分钟
- **画布超限**：多屏时苹果把所有屏拼成一整张大画面，超过手机浏览器的画布上限会直接黑屏
- **跟不上**：手机网慢时数据在路上越堆越多，操作越来越迟

所以在电脑上把画面解开，只留选中的那块屏（或那个窗口），默认缩到「点」的分辨率，压成 JPEG（noVNC 认的 Tight 编码）再发，第一帧几百 KB。手机要一帧才发一帧、只发变了的区域，网慢就自然跳帧，不在路上堆积。

握手和认证原样转（ARD 认证，凭据在手机上加密），只修两处兼容问题：版本号（苹果报 003.889，noVNC 回 003.008，苹果不认）和认证失败时补一段原因。换屏、换清晰度、看窗口、切回前台 app、改窗口大小、探测输入框用几条自定义消息（250 / 252 / 253 / 247 / 254），不用重新登录；代理的回复借 DesktopName 带回去（`[w]` 在看窗口、`[x]` 退回看屏的原因、`[r]` 请重连、`[k]` 输入框探测结果、`[z]` 改大小的结果）。

## 自动弹键盘怎么判断

转码代理收到 254 后问 mousectl 两个只读信号，都不碰 app 本身、不读输入框里的文字：

- **系统当前的鼠标指针是不是 I 形**：各种 app 在输入框上都会换成它，辅助功能看不到内容的 app（微信、Electron 这类）也一样
- **辅助功能里焦点控件的角色**（文本框、文本区、搜索框、组合框）和输入光标的位置，原生 app 才有

iOS 只允许在手指点的那一下里同步弹出键盘，等网络往返回来就晚了。所以手指一按下手机就先问一次（代理把光标挪过去但不点，等 app 换好指针再看形状）；抬手时结果已经到了、而且是输入框，就当场弹键盘。没赶上就点完再问一次，是输入框就在旁边浮一个「⌨ 打字」按钮，点它弹键盘。键盘弹出后画面放大到跟屏幕一样宽，把输入光标（拿不到就用点的位置）挪到键盘上面。横过来显示时不自动弹。

「前台 app」统一用辅助功能问系统（`AXFocusedApplication`），拿不到再取最上面那个普通窗口的主人：常驻的 mousectl 没有主循环，`NSWorkspace.frontmostApplication` 不会更新，会记错「切回」要切回的 app。

## 改窗口大小、关窗口、退出 app

- **改大小**：mousectl `w place` 用辅助功能直接设窗口的位置和大小（`AXPosition` / `AXSize`），不拖窗口边、不切前台。放大时先挪位置再改大小，免得超出屏幕被 app 截掉。不让改大小的窗口会提示
- **关窗口**：按这个窗口辅助功能里的关闭按钮（`AXCloseButton`），跟点红叉一样
- **退出 app**：`NSRunningApplication.terminate()`（正常退出）/ `forceTerminate()`（强制）；系统进程（访达、程序坞、登录窗口、控制中心等）mousectl 直接拒绝

## 踩过的 macOS 坑

- **多屏的位置对不上**：每块屏在整张画面里的位置不能按系统的屏幕坐标直接换算，有负坐标的排布下苹果会把有的屏左右挪一截。纵向可以算，横向要量：第一次连上时通过屏幕共享把光标挪到每块屏所在的那一行，读系统报的光标横坐标反推偏移（只用坐标，不看画面）。结果按显示器布局缓存在 `~/.cache/pane-remote/screen-layout.json`，布局不变下次直接用
- **苹果注入的鼠标只能在一排屏里动**：多屏时屏幕共享只能把光标的纵坐标放在其中一排屏里，别的屏点不到。所以鼠标改由 mousectl 直接发系统事件；mousectl 不在时才退回屏幕共享
- **输入法捣乱**：中文按键码发过去顺序会乱，电脑开着中文输入法时英文字母还会被它截走。所以文字一律由 mousectl 放进剪贴板再 ⌘V，打完一阵子再把你原来的剪贴板放回去
- **冷启动黑屏**：屏幕共享进程冷启动后的第一个登录连接整场都是黑画面（重新要画面也没用），紧接着重新登录一次就正常。系统日志显示，登录后屏幕共享会先唤醒主显示器，碰上显示器在低功耗状态时各块屏重新配置，它这一轮的采集就没开始。现在整块屏的画面默认来自 mousectl，碰不到这个问题；退回屏幕共享出画面时仍有兜底：转码代理在连上 15 秒内先不把全黑的画面发给手机（手机显示「屏幕共享正在启动」），一直全黑就让手机用刚输的密码马上重连一次（`[r]`）。密码只在手机内存里留 20 秒，用掉或过期就丢。试过连之前先用 `caffeinate -u` 叫醒显示器，结果第一帧有了、之后不再更新，比黑屏更糟，所以默认不做（环境变量 `VNC_PROXY_WAKE=1` 可以打开，只用于排查）
- **切到前台后还是只有旧截图**：偶尔窗口切到前台后 ScreenCaptureKit 仍然只给截图，截图是旧画面，看着像卡住。转码代理隔 3 秒重开实时录制，最多 3 次；只有截图时按一下画面也会再切一次前台、重开录制
- **别的桌面上的窗口没有实时画面**：ScreenCaptureKit 对不在当前桌面、或被台前调度收起的窗口不给实时帧。mousectl 先退成定时截图，转码代理随后自动把窗口切到前台再重新录（顶部会提示）
- **有的 app 预先建好隐藏窗口**：这些窗口在系统的窗口列表里看着跟正常窗口一样，按 app 自己的辅助功能窗口列表过滤掉
- **后台窗口收不到点击**：点击没法投递给不在前台的窗口，所以看窗口时第一次按下会先把它切到前台；键盘和文字在切过去之前可以直接发给那个 app 的进程，不抢前台

## 锁屏

- **锁屏时打字走屏幕共享**：锁屏界面的密码框是系统的安全输入，不接受粘贴，普通进程（mousectl）发的按键也进不去；屏幕共享是系统服务，它注入的按键能进。转码代理每秒查一次 `IOConsoleLocked`，锁着的时候把文字逐字、按键原样交给屏幕共享，解锁后换回 mousectl
- **锁屏时画面截得勤一点**：锁屏界面受保护，ScreenCaptureKit 不给实时画面只能截图，整块屏这时每秒截 8 次左右（窗口截图仍是每秒 3 次），打字不至于看着卡
- **断开后电脑又锁上**：从手机上通过屏幕共享解锁，断开连接后 macOS 会把屏幕重新锁上。这是苹果自己的安全行为（远程会话结束不留一个解锁的桌面），不是 pane-remote 的问题

## 要哪些权限

| 在哪 | 给谁 | 干什么用 |
|---|---|---|
| 系统设置 → 通用 → 共享 → 屏幕共享 | 打开，「允许访问」只留你自己的账号 | 画面和登录 |
| 系统设置 → 隐私与安全性 → 辅助功能 | mousectl | 点、拖、滚动、按键、粘贴文字、把窗口切到前台、改窗口大小、关窗口、自动弹键盘的焦点探测 |
| 系统设置 → 隐私与安全性 → 屏幕与系统录音 | mousectl | 整块屏和单个窗口的画面、窗口列表 |

另外要 Xcode 命令行工具（`xcode-select --install`），mousectl 是在你电脑上用 `swiftc` 现编的。

`pane-remote doctor` 会查屏幕共享开没开（只看 5900 端口有没有在监听，不去连它：每连一次屏幕共享都要接一个连接）、mousectl 在不在运行、转码要用的 sharp 能不能加载。

## 签名证书

macOS 的辅助功能、屏幕录制授权认的是程序的签名。编译器默认给的临时签名每次编译都不一样，所以每次更新重编 mousectl，授权就掉了，得去系统设置里重新打开。

`--create-cert` 在登录钥匙串里建一张名为 `pane-remote local signing` 的自签名代码签名证书（私钥只在本机，临时文件用完就删），之后 `install-mousectl.sh` 都用它签名，重编后授权不掉。建好证书后要再授权一次。`pane-remote update` 遇到 mousectl 有改动时：有证书就重编重签，授权不掉；没有证书就保留旧的 mousectl 并提示你。旧的 mousectl 不认新指令时：整块屏退回屏幕共享出画面，改窗口大小、关窗口、自动弹键盘这些新功能不可用，别的照常。第一次用它签名时钥匙串可能问一次要不要允许 codesign 使用，选「始终允许」。

没建证书时，安装脚本只在 mousectl 不存在时编译，避免白白掉授权。

## 限制

- 打字时会短暂占用剪贴板（打完不到 1 秒放回原来的内容），这期间你在电脑上复制的东西可能被覆盖
- 最小化的窗口录不到（会退回看屏并提示）
- 自动弹键盘靠鼠标指针形状和辅助功能猜，个别自己画指针的 app 会判断不准；iOS 的限制下有时要点一下「⌨ 打字」按钮
- 依赖苹果屏幕共享的行为和 macOS 的私有细节（多屏偏移、快捷键标志），系统升级后可能要调整
- 关掉模块：`pane-remote disable screen`，会顺带停掉并移除 mousectl

## 隐私

- **服务端看不到你的密码**：登录用屏幕共享自己的 ARD 认证，凭据在手机上用 Diffie-Hellman 协商的密钥加密，服务端、中转服务器和转码代理都只是原样转发
- 转码代理只处理它要转发的那部分像素（选中的屏或窗口），不存画面；日志里只有尺寸、字节数和平均亮度这类数字
- 输入框探测只读焦点控件的角色、输入光标位置和指针形状，不读输入框里的内容；日志里只记结果（是不是输入框、凭哪个信号）
- 显示器布局缓存（`~/.cache/pane-remote/screen-layout.json`）只记坐标
- 跟整个 pane-remote 一样，前提是这台 Mac 只有你自己在用：mousectl 的 socket 只有你的账号能读写，但能以你的身份跑程序的东西都能用它发鼠标键盘事件
