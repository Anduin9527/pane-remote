# 看屏幕模块

中文 | [English](en/screen.md)

在手机上看和操作电脑的屏幕：整块显示器，或者只看某一个窗口。画面来自 macOS 自带的「屏幕共享」，不用装第三方远程桌面软件。只支持 macOS，默认关闭。

```bash
pane-remote enable screen                 # 装鼠标助手 mousectl，并列出要你手动做的几步
pane-remote enable screen --create-cert   # 同上，另外建一张本机自签名证书给 mousectl 签名（见下文「签名证书」）
```

开启后手机顶栏会多一个屏幕图标，点开用电脑的用户名和密码登录。

## 能做什么

- **看一块显示器**：多屏时顶部有选屏按钮（★ 是主屏）；「省流」按「点」的分辨率发（像素少 4 倍），「清晰」按实际像素发
- **只看一个窗口**：「窗口」按钮列出所有能录的窗口（含别的桌面上的、台前调度收起来的），可以搜索。只录这一个窗口，不切到前台；第一次点它时才切到前台，「切回」把原来的前台 app 切回来
- **后台打开 app**：窗口列表下面是没开窗口的 app，「后台打开」不抢前台，窗口开出来后自动切过去看。只有菜单栏图标的 app 显示「唤出」：Spotlight 按系统设置里它的快捷键，uTools 按它自己设置里的唤出快捷键，别的点一下它的菜单栏图标
- **直接点模式**：轻点 = 点击，长按 = 右键，长按后拖 = 按住左键拖，单指滑 = 滚动，双指 = 缩放 / 平移（只在手机上放大，不影响电脑）
- **触控板模式**：手指滑动挪光标，轻点 = 在光标处点击，双指滑 = 滚动，双指捏 = 缩放（画面跟着光标走）
- **打字**：键盘按钮打开输入框，打的字整段发过去（含中文和输入法上屏的文字）；⌘ ⌥ ⌃ ⇧ 按钮对下一个键生效，比如先点 ⌘ 再打 c 就是复制；还有 Esc、Tab、方向键
- **多指手势**（跟 Mac 触控板一样，换成系统快捷键发过去）：三 / 四指上滑 = 调度中心，下滑 = 应用程序窗口（App Exposé），左右滑 = 切桌面，张开 / 捏合 = 显示桌面，三指轻点 = 查询（Look Up）
- **横过来**：竖着拿手机也能把整个界面转 90°，看宽屏方便

## 结构

```
手机 noVNC（web/src/lib/screen/ScreenView.svelte）
   │ WebSocket /api/screen/vnc?view=屏序号,清晰
   ▼
pane-remote 服务（server/screen.mjs，只转字节）
   │ bridge 的 screen 指令（local 模式直接执行，relay 模式经 SSH 反向隧道）
   ▼
转码代理（agent/screen/proxy.mjs，电脑上）──── 鼠标、键盘、文字、窗口画面 ──── mousectl（LaunchAgent，unix socket）
   │ RFB，127.0.0.1:5900
   ▼
macOS 屏幕共享
```

窗口列表、app 列表、后台打开走普通的 HTTP 接口（`GET /api/screen/displays|windows|apps`、`POST /api/screen/launch|summon`），最后也是 bridge 去问 mousectl。

## 为什么要转码代理

直接把屏幕共享的数据转给手机不行：

- **太大**：苹果的屏幕共享只给 ZRLE 编码，对照片、壁纸几乎压不动，一块 4K 屏第一帧就十几 MB；relay 模式下中转服务器带宽小时要等半分钟
- **画布超限**：多屏时苹果把所有屏拼成一整张大画面，超过手机浏览器的画布上限会直接黑屏
- **跟不上**：手机网慢时数据在路上越堆越多，操作越来越迟

所以在电脑上把画面解开，只留选中的那块屏（或那个窗口），默认缩到「点」的分辨率，压成 JPEG（noVNC 认的 Tight 编码）再发，第一帧几百 KB。手机要一帧才发一帧、只发变了的区域，网慢就自然跳帧，不在路上堆积。

握手和认证原样转（ARD 认证，凭据在手机上加密），只修两处兼容问题：版本号（苹果报 003.889，noVNC 回 003.008，苹果不认）和认证失败时补一段原因。换屏、换清晰度、看窗口用几条自定义消息（250 / 252 / 253），不用重新登录。

## 踩过的 macOS 坑

- **多屏的位置对不上**：每块屏在整张画面里的位置不能按系统的屏幕坐标直接换算，有负坐标的排布下苹果会把有的屏左右挪一截。纵向可以算，横向要量：第一次连上时通过屏幕共享把光标挪到每块屏所在的那一行，读系统报的光标横坐标反推偏移（只用坐标，不看画面）。结果按显示器布局缓存在 `~/.cache/pane-remote/screen-layout.json`，布局不变下次直接用
- **苹果注入的鼠标只能在一排屏里动**：多屏时屏幕共享只能把光标的纵坐标放在其中一排屏里，别的屏点不到。所以鼠标改由 mousectl 直接发系统事件；mousectl 不在时才退回屏幕共享
- **输入法捣乱**：中文按键码发过去顺序会乱，电脑开着中文输入法时英文字母还会被它截走。所以文字一律由 mousectl 放进剪贴板再 ⌘V，打完一阵子再把你原来的剪贴板放回去
- **冷启动黑屏**：屏幕共享进程冷启动后的第一个登录连接整场都是黑画面（重新要画面也没用），紧接着重新登录一次就正常。转码代理发现连上 15 秒内画面一直全黑，就让手机用刚输的密码马上重连一次。密码只在手机内存里留 20 秒，用掉或过期就丢
- **别的桌面上的窗口没有实时画面**：ScreenCaptureKit 对不在当前桌面、或被台前调度收起的窗口不给实时帧。mousectl 先退成定时截图，转码代理随后自动把窗口切到前台再重新录（顶部会提示）
- **有的 app 预先建好隐藏窗口**：这些窗口在系统的窗口列表里看着跟正常窗口一样，按 app 自己的辅助功能窗口列表过滤掉
- **后台窗口收不到点击**：点击没法投递给不在前台的窗口，所以看窗口时第一次按下会先把它切到前台；键盘和文字在切过去之前可以直接发给那个 app 的进程，不抢前台

## 要哪些权限

| 在哪 | 给谁 | 干什么用 |
|---|---|---|
| 系统设置 → 通用 → 共享 → 屏幕共享 | 打开，「允许访问」只留你自己的账号 | 画面和登录 |
| 系统设置 → 隐私与安全性 → 辅助功能 | mousectl | 点、拖、滚动、按键、粘贴文字、把窗口切到前台 |
| 系统设置 → 隐私与安全性 → 屏幕与系统录音 | mousectl | 只看一个窗口、窗口列表 |

另外要 Xcode 命令行工具（`xcode-select --install`），mousectl 是在你电脑上用 `swiftc` 现编的。

`pane-remote doctor` 会查屏幕共享开没开（5900 端口）、mousectl 在不在运行、转码要用的 sharp 能不能加载。

## 签名证书

macOS 的辅助功能、屏幕录制授权认的是程序的签名。编译器默认给的临时签名每次编译都不一样，所以每次更新重编 mousectl，授权就掉了，得去系统设置里重新打开。

`--create-cert` 在登录钥匙串里建一张名为 `pane-remote local signing` 的自签名代码签名证书（私钥只在本机，临时文件用完就删），之后 `install-mousectl.sh` 都用它签名，重编后授权不掉。建好证书后要再授权一次。第一次用它签名时钥匙串可能问一次要不要允许 codesign 使用，选「始终允许」。

没建证书时，安装脚本只在 mousectl 不存在时编译，避免白白掉授权。

## 限制

- 锁屏界面的密码框可能不接受粘贴进去的文字，这时只能到电脑前解锁（或者先让电脑别锁屏）
- 打字时会短暂占用剪贴板（打完不到 1 秒放回原来的内容），这期间你在电脑上复制的东西可能被覆盖
- 最小化的窗口录不到（会退回看屏并提示）
- 依赖苹果屏幕共享的行为和 macOS 的私有细节（多屏偏移、快捷键标志），系统升级后可能要调整
- 关掉模块：`pane-remote disable screen`，会顺带停掉并移除 mousectl

## 隐私

- **服务端看不到你的密码**：登录用屏幕共享自己的 ARD 认证，凭据在手机上用 Diffie-Hellman 协商的密钥加密，服务端、中转服务器和转码代理都只是原样转发
- 转码代理只处理它要转发的那部分像素（选中的屏或窗口），不存画面；日志里只有尺寸、字节数和平均亮度这类数字
- 显示器布局缓存（`~/.cache/pane-remote/screen-layout.json`）只记坐标
- 跟整个 pane-remote 一样，前提是这台 Mac 只有你自己在用：mousectl 的 socket 只有你的账号能读写，但能以你的身份跑程序的东西都能用它发鼠标键盘事件
